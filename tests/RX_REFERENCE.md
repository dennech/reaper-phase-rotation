# Reference measurements in iZotope RX 10 Advanced (Phase module)

Measured on 2026-09-14 with RX 10 Advanced (macOS, Apple Silicon). Files were
generated by `tests/make_rx_ref.sh`, opened in RX, *Select All*, Phase module
→ **Suggest**, then **Render** and *File → Overwrite Original File*. The saved
files were compared with this project's reference implementation
(`tests/reference.py`).

## Suggested angles

| File (mono, 48 kHz)   | RX Suggest | Ours, RX criterion (L8) | Ours, min-peak criterion |
|-----------------------|-----------:|------------------------:|-------------------------:|
| asym_mono.wav (synth) |      +78°  |                 +77.6°  |                  +73.5°  |
| speech_en.wav (TTS)   |      +62°  |                 +62.3°  |                  +77.1°  |
| speech_ru.wav (TTS)   |      +78°  |                 +77.5°  |                  +98.4° (= −81.6°) |

RX displays whole degrees. Minimising `Σ|y|^8` (an L8 norm - a smooth
"peak" measure) reproduces RX's choice on all three files to within 0.5°;
other candidates that were tried (exact sample peak, true peak, percentiles,
per-frame peak sums, crest factors, skewness, high-passed peaks, L4…L16 norms)
do not. L7 and L9 are already off by 1–2°. The exact sample-peak minimum
gives 0.3–0.6 dB more headroom than RX's angle on these files; it is available
in the script as the alternative "Minimum sample peak" criterion.

Peak levels (dBFS) of RX's renders vs. the min-peak optimum:

| File          | before | RX output (pos / neg)        | min-peak optimum |
|---------------|-------:|------------------------------|-----------------:|
| asym_mono     |  −6.02 | −8.89 (−9.36 / −8.89)        |           −9.25  |
| speech_en     |  −1.65 | −2.63 (−2.63 / −4.08)        |           −3.21  |
| speech_ru     |  −2.64 | −3.15 (−3.15 / −4.75)        |           −3.87  |

## Sign convention and DSP

Fitting RX's rendered output `o` against `x` and its Hilbert transform
`H{x}` (least squares) gives

```
o = cos(θ)·x + sin(θ)·H{x},  θ = +78.00° / +62.00° / +78.00°,  gain 0.9997–1.0000, lag 0 samples
```

i.e. RX's displayed angle is exactly the θ in the formula above (this
project uses the same convention), there is no time shift, and the residual
between RX's render and our FIR-Hilbert rotation is −80 dB or lower above
50 Hz (−30 dB at 20–50 Hz, −14 dB below 20 Hz: RX's Hilbert transformer is
shorter/less accurate at very low frequencies than our 8193-tap FIR). Max
sample difference 3.5e-3 on asym_mono (which has strong low harmonics) and
9.8e-4 on speech_en.

## Adaptive phase rotation

`speech_ru.wav` was also processed in RX with **Adaptive phase rotation** on (Render →
Overwrite Original File). A local least-squares fit of the output against `x` and `H{x}`
in 20 ms windows shows that RX's output is still a pure rotation at every instant
(relative residual 0.1 %) with a time-varying angle (+11° … +112°, changing at up to
~120°/s), i.e. the same DSP with a tracked angle.

| speech_ru, peak (dBFS)                        | overall | per-second vs RX (mean / worst) |
|-----------------------------------------------|--------:|--------------------------------:|
| original                                      |  −2.64  |                                 |
| RX fixed Suggest (+78°)                       |  −3.15  |                                 |
| RX adaptive                                   |  −4.19  |                                 |
| ours, adaptive (extension and JSFX)           |  −4.14  |          −0.23 dB / +0.09 dB    |

Our adaptive estimator: per 43 ms sub-block the peak-minimising angle (2° bins,
hysteresis between near-equal minima, silence holds the previous value), linearly
interpolated between sub-block centres with one sub-block of look-ahead. A causal
one-pole smoother (the first implementation) was 0.6–1 dB worse than RX; the
interpolated version matches it.

## Reproducing

```bash
tests/make_rx_ref.sh /tmp/rx_ref .venv/bin/python
# open /tmp/rx_ref/*_orig.wav in RX, Select All, Phase → Suggest, note the angle
# then: PR_RX_REF_DIR=/tmp/rx_ref PY=.venv/bin/python tests/run_tests.sh /tmp/phase-tests
```

The test suite checks that our Suggest on `asym_mono.wav` stays within 1° of
RX's +78° (always), and on the two speech files when `PR_RX_REF_DIR` is set.
