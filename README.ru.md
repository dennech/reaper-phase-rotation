# Phase Rotation (RX-style) для REAPER

Аналог модуля **Phase из iZotope RX** для айтемов REAPER. [English README](README.md).

Голос почти всегда записывается несимметрично: положительные и отрицательные пики разной
высоты. Поворот фазы всех частот на один и тот же угол не меняет звучание, но
перераспределяет пики — форма волны выравнивается по центру, появляется запас по уровню.
Здесь есть всё то же, что в RX: **Suggest**, слайдеры **Left/Right rotation** со связкой,
**Adaptive phase rotation**, **Preview / Bypass**.

| В RX                      | Здесь                                                                        |
|---------------------------|------------------------------------------------------------------------------|
| Suggest                   | Анализирует каждый выделенный айтем и выставляет подсказанный угол на слайдеры (айтем пока не меняется). Воспроизводит значения Suggest самого RX 10 (проверено по рендерам RX, см. `tests/RX_REFERENCE.md`); есть и критерий «минимальный пик» |
| Left / Right rotation [°] | Слайдеры −180…+180, поле ввода (клик — ввести число), кнопка Link             |
| Adaptive phase rotation   | Угол пересчитывается каждые ~43 мс с плавными переходами (в обоих движках)    |
| Preview / Bypass          | Preview играет айтем с черновыми настройками, проект и волна не меняются; Bypass выключает и включает уже применённый поворот |
| Apply                     | Записывает черновые настройки в айтемы (одна точка Undo). С расширением поворот применяется к источнику айтема: волна меняется сразу, ничего не пишется на диск и не вешается на айтем |
| Render                    | С расширением не нужен (см. Apply); в запасном режиме take FX есть, чтобы запечь JSFX |
| *(в RX нет)*              | Меню **Rotator**: кроме прозрачного RX-поворота есть вещательный **allpass-ротатор** (Orban 4 × 200 Гц, старый VoicePhaseRotator 8 × 200 Гц, свой) — см. ниже |
| Compare                   | Не реализовано — используйте Bypass и Undo                                    |

## Два движка

**Движок «источник» (рекомендуется)** — с установленным расширением `reaper_phaserot`
скрипт применяет поворот к *источнику* тейка на лету. Воспроизведение, рендер, glue и
**отрисовка волны** показывают повёрнутый звук; файлы не пишутся, take FX не добавляется,
задержки нет. Файл проекта остаётся обычным: тейк по-прежнему ссылается на исходный
`<SOURCE WAVE>`, а поворот хранится в строке тейка `P_EXT:phaserot`, которую REAPER
сохраняет в проекте и в состояниях Undo (Undo/Redo, копирование, дублирование работают).
REAPER без расширения открывает такой проект штатно и играет *исходный, неповёрнутый*
звук — ничего не уходит в оффлайн; чтобы услышать и увидеть поворот, достаточно поставить
расширение через ReaPack.

**Движок take FX (запасной)** — без расширения вставляется JSFX **«Phase Rotation
(RX-style, Hilbert)»** как take FX. Звук обрабатывается вживую, но REAPER рисует волну по
исходнику, поэтому картинка не меняется; в этом режиме есть кнопка *Render* (новый тейк).

Знак угла — как в RX; значения Suggest совпадают с RX (см. ниже).

## Установка

### ReaPack (рекомендуется)

1. Extensions → ReaPack → Import repositories…
2. Вставьте `https://github.com/dennech/reaper-phase-rotation/raw/main/index.xml`
3. Установите **Phase Rotation (RX-style).lua** (JSFX идёт вместе с ним) и расширение
   **reaper_phaserot** (категория Extensions; macOS universal, Windows x64, Linux x86_64 /
   aarch64), затем перезапустите REAPER.

### Вручную

1. Скопируйте папку `Items` в `<ресурсы REAPER>/Scripts/` (можно переименовать, например
   `Scripts/Phase Rotation/`). Три файла должны лежать вместе:
   `Phase Rotation (RX-style).lua`, `phase_rotation_core.lua`, `phase_rotation.jsfx`.
2. Actions → Show action list → *New action…* → *Load ReaScript…* → выберите `.lua`.
3. При первом запуске скрипт сам скопирует `phase_rotation.jsfx` в
   `Effects/Phase Rotation/`, чтобы REAPER мог его загрузить.
4. Расширение: положите `reaper_phaserot.dylib` / `.dll` / `.so` (из релиза на GitHub или
   соберите сами — `extension/README.md`) в `<ресурсы REAPER>/UserPlugins/` и перезапустите
   REAPER. Активный движок скрипт показывает в правом нижнем углу окна.

Нужен REAPER 6.x или новее (проверено на 7.80, macOS). Другие расширения не нужны
(обычный `gfx`-интерфейс, без ReaImGui / SWS / js_ReaScriptAPI).

## Как пользоваться

Схема работы как в RX: пока не нажат **Apply**, ничего не меняется.

1. Выделите один или несколько **аудио-айтемов** (моно или стерео).
2. Запустите действие **Script: Phase Rotation (RX-style).lua**.
3. Нажмите **Suggest** (или `S`). Для каждого айтема считается свой анализ; подсказанные
   углы встают на слайдеры, в окне видны пик до/после и выигрыш по запасу. Сами айтемы пока
   не тронуты.
4. **Preview** (`Space`) играет айтем с черновыми настройками, а проект, история Undo и
   волна остаются в применённом состоянии. Слайдеры можно двигать во время прослушивания
   (Shift — точно, колесо — по 1°, двойной клик — 0°, клик по значению — ввести число);
   оранжевая риска на слайдере отмечает применённое значение.
5. **Apply** (`A`) записывает черновые настройки во все выделенные айтемы (одна точка
   Undo). С движком «источник» волна обновляется сразу. **Revert** возвращает слайдеры к
   применённым значениям, **Bypass** (`B`) сравнивает применённый поворот с оригиналом,
   **Reset** убирает его. Всё отменяется через Undo.

Множественное выделение: **Suggest / Apply / Bypass / Reset / Adaptive / Link / Rotator
действуют на все выделенные айтемы**, слайдеры правят айтем, показанный в навигаторе
*Item i / n*.

Если привычнее старое поведение (слайдеры и Suggest меняют айтем сразу), включите
*Apply changes instantly* в меню `...`. Там же включается полярный график «огибающая × фаза».

### Типы ротатора

* **RX-style** (по умолчанию): один угол для всех частот. Сам по себе не слышен, меняются
  только форма волны и пики. Так работает RX.
* **Allpass rotator**: вещательный «фазовращатель» — каскад одинаковых allpass-звеньев
  около 200 Гц, как в FM-процессорах с 1970-х. Пресеты: *Orban classic* (4 звена первого
  порядка на 200 Гц, схема из документации Orban), 2 и 6 звеньев, *VoicePhaseRotator*
  (8 звеньев второго порядка на 200 Гц с Q 0,35, то есть 16 звеньев первого порядка;
  восстановлен по старому бесплатному VST с таким названием) и свой вариант (порядок,
  число звеньев, частота, Q). В отличие от RX-поворота этот слышен: низ опаздывает
  относительно верха на единицы–десятки миллисекунд (около 6 мс у Orban 4 × 200 Гц, 34 мс
  на 25 Гц у VoicePhaseRotator), атаки смягчаются, голос звучит плотнее — тот самый
  эффект «как компрессия», за который такие приборы ценят. RMS и спектр не меняются, это
  линейный фильтр. Относитесь к нему как к обработке: слушайте, а на все микрофоны одного
  источника ставьте одинаковую настройку. Слайдеры RX-поворота остаются доступны после
  него как точная подстройка, Suggest считает угол уже для сигнала после allpass.

**Adaptive phase rotation** следует за сигналом вместо одного фиксированного угла —
полезно, когда асимметрия меняется во времени (несколько дикторов, длинные дубли). На
речевом эталоне он даёт те же пиковые уровни, что адаптивный режим RX (см.
`tests/RX_REFERENCE.md`). Сглаживание — в меню `...`. Как и в RX, режим рассчитан на речь;
на музыке обычно чище фиксированный угол.

JSFX можно использовать и отдельно (как track FX или take FX) — органы управления те же.

## Как это работает

* **Поворот**: `y = cos(θ)·x + sin(θ)·H{x}` (знак как в RX), где `H` — линейно-фазовый FIR-преобразователь
  Гильберта (окно Кайзера, 8193 отвода при ≤ 50 кГц, 16385 выше), применяемый FFT-свёрткой
  overlap-save. Ровный в пределах 0,01 дБ от 14 Гц. При 0° выход побитово равен входу;
  в JSFX задержка (блок + один подблок упреждения + задержка FIR, около 300 мс при 48 кГц)
  объявлена как PDC и полностью компенсируется REAPER — ничего не сдвигается во времени;
  расширение читает вперёд само и задержки не имеет.
* **Suggest**: анализ на Lua считает тот же Гильберт (через встроенный FFT REAPER), строит
  гистограммы огибающей аналитического сигнала по фазе (шаг 0,125°) и ищет угол,
  минимизирующий `Σ|y|^8` — норму L8, «сглаженный пик». Именно этот критерий
  воспроизводит значения Suggest у iZotope RX 10 (+78° / +62° / +78° на трёх эталонных
  файлах, у нас +77,6° / +62,3° / +77,5°; подробности в `tests/RX_REFERENCE.md`).
  Альтернативный критерий (меню `...`) минимизирует точный сэмпловый пик `max |y|` и даёт
  на 0,3–0,6 дБ больше запаса, чем угол RX. 90 секунд стерео анализируются за ~0,4 с.
* **Adaptive**: угол минимального пика оценивается на подблоках по 43 мс (гейт на тишине,
  гистерезис между близкими минимумами) и линейно интерполируется между центрами подблоков
  с упреждением на один подблок — и в расширении (считается один раз на тейк), и в JSFX
  (с PDC).
* **Allpass-ротатор**: звенья первого порядка `c = (tg(πf₀/fs) − 1) / (tg(πf₀/fs) + 1)`,
  звенья второго порядка — allpass-биквады RBJ (`α = sin ω₀ / 2Q`); рассчитываются на
  частоте дискретизации источника и работают перед преобразованием Гильберта. Расширение
  хранит состояние фильтра между последовательными чтениями и «разогревает» его на 0,5 с
  перед чтением с произвольной позиции, поэтому воспроизведение, отрисовка и анализ
  совпадают с эталоном numpy с точностью до сэмпла.
* **Preview** (движок «источник»): обёртка получает отдельный набор параметров только для
  воспроизведения — аудиопоток играет черновые настройки, а пики, проект и Undo хранят
  применённые. Ничего не сохраняется.

## Ограничения

* Обрабатываются целые айтемы. Чтобы обработать участок — сначала разрежьте айтем.
* Стерео анализируется по каналам; при включённом **Link** берётся общий угол (как в RX).
  У айтемов с более чем двумя каналами обрабатываются каналы 1–2, остальные проходят без
  изменений.
* Анализ берёт ту часть источника, которую играет айтем (смещение, длина, playrate), и channel mode тейка, но не другие take FX.
* Критерий — *сэмпловый* пик, как в RX. Одиночный щелчок может его перевесить — сначала
  уберите щелчки или задайте угол на слух.
* Только движок take FX: при живом воспроизведении JSFX добавляет ~300 мс PDC-задержки; на
  рендер это не влияет. У движка «источник» задержки нет.
* Движок «источник»: пики для отрисовки повёрнутого тейка REAPER пересчитывает по запросу
  (около 0,3 с на 10 минут звука после каждого изменения).
* Изменения во время Preview доходят до звука с задержкой медиабуфера REAPER (до секунды),
  как любое изменение источника при воспроизведении.

## Тесты

`tests/reference.py` — независимая реализация на numpy (расчёт FIR, поиск угла,
синтетические асимметричные «голосовые» сигналы). `tests/run_tests.sh` собирает
расширение, запускает изолированный экземпляр REAPER (отдельная папка ресурсов, ваш конфиг
не трогается), выполняет `tests/run_in_reaper.lua` (движок JSFX: анализ, рендер с
фиксированными углами, проверка PDC, адаптивный рендер, обход трековых FX),
`tests/ext_test.lua` (движок «источник»: выход против эталона, пики волны, Undo/Redo,
дублирование, сохранение/загрузка, bypass/reset, адаптивный режим, allpass-пресеты,
непрерывность при перемотке, preview) и `tests/gui_smoke.lua` (сценарий кликов через
настоящий UI: Suggest не должен применять, Apply — должен, а звук применённого айтема
читается обратно через REAPER и сверяется с цепочкой numpy) и сверяет результаты с эталоном: углы совпадают до
0,35° (шаг гистограммы анализа 0,125°), звук — до ~1e-6. В `tests/RX_REFERENCE.md` — сравнение с iZotope RX 10 (углы, знак,
отрендеренное аудио).
